# AI Skills — ทะเบียนกฎหมาย SHE

ระบบมี AI Skill 2 ตัว ทำงานเป็น Vercel serverless function เรียกจากหน้า **สรุปกฎหมาย** (`src/pages/LawSummary.jsx`)
ต้องตั้ง env `ANTHROPIC_API_KEY` (และเลือกได้ `ANTHROPIC_MODEL` — ค่าเริ่มต้น `claude-sonnet-4-6`)

---

## โฟลว์ 2 คำขอ (P16)

การสรุป 1 ครั้งยิง **2 คำขอเรียงกัน** ไม่ใช่คำขอเดียว

```
คำขอ 1  POST /api/law-analyze  { relate: false }   → ตารางฉบับหลัก ขึ้นทันที
คำขอ 2  POST /api/law-relate   { refs: pending_refs }  → เติมข้อจากกฎหมายที่อ้างถึง
```

**ทำไมต้องแยก:** เดิมทำ 4 ด่านต่อกันในคำขอเดียว (สรุปฉบับหลัก → Skill 3 ชั้น 1 → ชั้น 2 → เรียบเรียงข้อ)
รวมแล้วชนเพดาน `maxDuration` 300 วิของ Vercel เป็นประจำ โค้ดจึงต้องข้ามงานทิ้งเมื่อเวลาไม่พอ
ผลคือ **ได้ข้อมูลไม่ครบ ไม่ใช่แค่ช้า** · แยกแล้วแต่ละฝั่งได้ 300 วิของตัวเอง และผู้ใช้เห็นตารางก่อน

คำขอที่ 2 ล้มเหลว **ไม่ล้างผลของคำขอแรก** — หน้าเว็บขึ้นปุ่ม "ลองเติมกฎหมายที่อ้างถึงอีกครั้ง"
ยิงซ้ำเฉพาะด่านนั้น ซึ่งเร็วขึ้นมากเพราะ cache

## Skill 1+2 — อ่าน / วิเคราะห์ / สรุปกฎหมาย
ไฟล์: `api/law-analyze.js`

**Input**
```
POST /api/law-analyze
{ "source": "<URL หรือ ตัวบท>", "kind": "auto|text",
  "pdfBase64": "<ไฟล์ PDF>", "sourceUrl": "", "stage": false, "relate": false }
```
รับได้ 3 ทาง: **ลิงก์ไฟล์ .pdf** (Claude ดึงเอง) · **แนบไฟล์ PDF** (≤4.5MB) · **ลิงก์หน้าเว็บ/วางข้อความ**
`relate: false` = คืนผลฉบับหลักอย่างเดียว (ค่าเริ่มต้นคือ `true` เพื่อความเข้ากันได้กับของเดิม)

**สิ่งที่สกัดออกมา**
- ระดับกฎหมาย: ชื่อเต็ม · ประเภท · กระทรวง · วันที่ประกาศ · **กฎวันบังคับใช้** · เอกสารที่ต้องจัดทำ ·
  หมวด (LA–LG) · เลขอ้างอิงราชกิจจาฯ (`gazette_ref`) · **บทยกเลิก** (`repeals`)
- ระดับข้อกำหนด: เลขมาตรา/ข้อ · เนื้อหา · `source_excerpt` · ผู้รับผิดชอบ · ขอบเขต · วิธีปฏิบัติ · เอกสาร · ความถี่ · โทษ
- กฎหมายที่ถูกอ้างถึง (`related_laws`) พร้อม `appears_in` และ `needs_lookup`

**การตรวจสอบฝั่งโค้ด (ไม่เชื่อ AI ตรงๆ)**
| ด่าน | ไฟล์ | ทำอะไร |
|---|---|---|
| วันบังคับใช้ | `_lib/effective-date.js` | AI บอกแค่ "ใช้กฎข้อไหน กี่วัน" **โค้ดบวกวันเอง** · กฎที่อ้างว่าตัวบทเขียนไว้ต้องมี `excerpt` ยืนยัน · ตัวบทไม่ระบุ = `not_stated` ใช้วันประกาศเป็นค่าตั้งต้นพร้อมป้ายเตือน |
| ตัวเลขแต่งเติม | `_lib/verify-numbers.js` | อ่านตัวเลขไทยทั้ง 3 แบบ (อารบิก · เลขไทย · คำไทย) แล้วเทียบว่าตัวเลขใน `req_text` มีที่มาใน `source_excerpt` จริง · ไม่ตรง = ติดป้ายเตือน ไม่ลบ |
| อ้างถึงจริงหรือเปล่า | `law-analyze.js` (`verifyRelatedRefs`) | `appears_in` ต้องคัดข้อความคำต่อคำ แล้วเทียบกับตัวบทจริง · ไม่ผ่าน = ไม่ตามไปดึง (กันเสียเงินฟรี) |
| แตกข้อความจาก PDF | `pdf-parse` (lazy import) | ใช้เป็นหลักฐานให้ 2 ด่านบน · ราชกิจจาฯ บางฉบับฝังฟอนต์ที่ถอดรหัสไม่ออก จึงมีด่านวัดคุณภาพก่อนใช้ (อักขระไทย ≥60% + เจอคำที่ตัวบทกฎหมายต้องมี ≥2 คำ) ไม่ผ่าน = ถอยไปโหมดตรวจอ่อน |

**Output** — `{ law, requirements, repeals, pending_refs, rejected_count, effective_source, effective_note, ... }`
`stage: true` (ค่าเริ่มต้น) จะเขียนลง `lg_import_staging` ด้วย · หน้าเว็บใช้ `stage: false` แล้วเก็บเองผ่าน `lg_ai_discovered_laws`

## Skill 3 — ตามอ่านกฎหมายที่ตัวบทอ้างถึง
ไฟล์: `api/_lib/osh-law-relate.js` · endpoint `api/law-relate.js`

**ปัญหาที่แก้:** กฎกระทรวงมักไม่เขียนซ้ำสิ่งที่อยู่ใน พ.ร.บ. แม่ · จป. ที่อ่านเฉพาะกฎกระทรวงจึงตกข้อกำหนดโดยไม่รู้ตัว
และข้อที่ลงท้ายว่า "ตามมาตรา 86/4 แห่งประมวลรัษฎากร" อ่านจบแล้วยังไม่รู้ว่าต้องทำอะไร

**เป้าหมายหลักคือ "อธิบายสาระ" ไม่ใช่ "หาข้อที่บริษัทต้องทำ"**
แต่ละฉบับที่ดึงมาต้องคืน `explain` (สาระภาษาชาวบ้าน) + `explain_excerpt` **เสมอ**
ไม่ว่ามาตรานั้นจะสร้างหน้าที่ให้บริษัทหรือไม่ — เพราะระบบเอา `explain` ไปเขียนแทนคำว่า "ตามมาตรา X"
ในข้อของฉบับหลัก (`inlineSectionRefs`) ให้ผู้อ่านอ่านจบในตัว

**ด่านตรวจ 4 ด่าน**
1. **(ก) โดเมน** — `source_url` ต้องอยู่ใน `TRUSTED_DOMAINS` ไม่ผ่าน = ทิ้งทั้งก้อน
2. **(ข) หลักฐาน** — ทุก requirement ต้องมี `source_excerpt` จากตัวบทจริง · `explain` ต้องมี `explain_excerpt`
3. **(ค) เพดานข้อ** — สูงสุด `MAX_REQ_PER_LAW` (15) ข้อต่อกฎหมาย 1 ฉบับ
4. **(ง) ไม่เหลือข้อ** — มี `explain` = สถานะ `explained` (ไม่ใช่ความล้มเหลว ไม่นับเป็นงานค้าง) · ไม่มี = `not_found`

**ความลึก** — ชั้น 1 ดึงทุกฉบับที่ `needs_lookup: true` · **ชั้น 2 ตามต่อเฉพาะการมอบอำนาจ**
คือฉบับชั้น 1 อ่านแล้วยังชี้ต่อ ("เงื่อนไขจริงอยู่ในกฎกระทรวงฉบับนั้น") ตัดสินจากธง `is_delegation` หรือรูปแบบข้อความ
เพดานรวม `MAX_TOTAL_LOOKUPS` = 12 ฉบับทุกชั้นรวมกัน · ชั้น 2 สูงสุด 4

**cache `lg_law_refs` (180 วัน)** — เก็บผลรายฉบับด้วย `ref_key` ที่ normalize ชื่อกฎหมายแล้ว
(`"พ.ร.บ. ความปลอดภัยฯ พ.ศ.๒๕๕๔"` กับ `"พระราชบัญญัติความปลอดภัย พ.ศ. 2554"` ต้องได้ key เดียวกัน)
**เก็บผลที่หาไม่เจอด้วย** เพื่อไม่ให้ยิงซ้ำทุกครั้ง · ยิงซ้ำครั้งที่ 2 จึงเร็วขึ้นมาก

**งบเวลา** — ทุกขั้นตอนรู้เวลาที่เหลือ (`FN_BUDGET_MS` 255 วิ) หมดเวลาแล้ว **คืนผลที่ได้พร้อมบอกว่าอะไรยังไม่ได้ทำ**
(`skipped_for_time`) ไม่ปล่อยให้ 504 ซึ่งเสียทั้งผลและเงินที่จ่ายไปแล้ว
ตัวเลขนี้ต้องขยับตาม `maxDuration` ใน `vercel.json` เสมอ

**ลดเวลาโดยไม่ลดความแม่น** — เดิมอ่านไฟล์ PDF ซ้ำเสมอเมื่อ `source_url` เป็น `.pdf`
ตอนนี้ข้ามรอบสองเมื่อผลจาก web_search ผ่านด่านครบแล้ว (resolved + โดเมนเชื่อถือได้ + มี excerpt ครบ)
กรณีอื่นยังอ่านไฟล์จริงตามเดิมทุกกรณี · ข้ามแล้วบันทึก note `"ใช้ผลจากการค้นโดยตรง (ผ่านด่านตรวจครบ)"` ไว้ตรวจย้อน
