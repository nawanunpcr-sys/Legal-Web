## 5 · ข้อจำกัดที่ต้องแจ้งฝ่าย IT — ห้ามละเว้น

### 5.1 ยังไม่มีบัญชีผู้ใช้รายคน (โหมด demo)
ล็อกอินเป็นการเลือกบทบาทจากหน้าจอ ไม่มีรหัสผ่านรายคน ชื่อผู้ประเมิน/ผู้ยืนยันที่บันทึกลงฐาน
มาจากชื่อที่ตั้งไว้ในหน้าตั้งค่า — **ใครก็ตามที่เปิดเว็บได้ สามารถบันทึกในนามใครก็ได้**
ผลกระทบ: ร่องรอยการตรวจสอบ (audit trail) ยังไม่มีน้ำหนักทางกฎหมาย
ต้องย้ายไป Supabase Auth ก่อนใช้เป็นหลักฐานในการตรวจประเมินจริง

### 5.2 RLS เป็น permissive public ทุกตาราง
ทุกตารางตั้ง `FOR ALL USING (true) WITH CHECK (true)` และแอปยิงด้วย anon key ตรงเข้า PostgREST
**ใครที่รู้ URL และ anon key อ่านและแก้ข้อมูลทั้งฐานได้** โดยไม่ต้องผ่านหน้าเว็บ
anon key อยู่ในไฟล์ JavaScript ที่เบราว์เซอร์ดาวน์โหลด จึงถือว่าเป็นข้อมูลสาธารณะ
ด่านที่ยังทำงานจริงมีเพียง CHECK constraint ในฐานข้อมูล ซึ่งกันได้แค่ข้อมูลผิดรูป ไม่ได้กันสิทธิ์
ต้องรัดเป็น `authenticated` พร้อมกันทั้งระบบเมื่อย้ายไป Supabase Auth

### 5.3 Rate limit เก็บในหน่วยความจำ นับไม่ตรงข้าม serverless instance
`api/_lib/guard.js` เก็บตัวนับใน Map ของ process · Vercel สร้าง instance ใหม่ได้ตลอดเวลา
ตัวนับจึงรีเซ็ตเองโดยไม่มีใครรู้ **โควตา 10 ครั้ง/นาที จึงเป็นเพียงเบรกกันกดรัว ไม่ใช่การป้องกันจริง**
ถ้าต้องการของจริงต้องย้ายตัวนับไปที่ Redis หรือตาราง Postgres

### 5.4 ไม่มี Vercel Cron — คิวไม่เดินเอง
`api/queue-run.js` ออกแบบให้ต่อ cron ได้ทันที แต่ยังไม่ได้ตั้ง ผู้ใช้ต้องกดปุ่ม "ประมวลผลคิว" เอง
ถ้าจะตั้ง cron **ต้องเพิ่มการตรวจ `CRON_SECRET` ก่อน** เพราะ cron ไม่มี Origin ให้ `sameOrigin()` ตรวจ
ปล่อยไว้เท่ากับเปิด endpoint ให้ใครก็เรียกได้

### 5.5 ผลจาก AI ไม่เคยผ่านการทวนสอบอัตโนมัติ
ระบบบังคับให้คนกดยืนยันทุกจุดก่อนข้อมูลกลายเป็นทางการ แต่ไม่มีกลไกตรวจว่า AI พูดถูกหรือไม่
สรุปของ AI **ใช้ทำความเข้าใจ ไม่ใช้แทนตัวบท** — ก่อนอ้างอิงกับผู้ตรวจต้องเปิดตัวบทจริงเสมอ
