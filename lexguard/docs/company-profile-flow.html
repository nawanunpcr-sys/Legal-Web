บล็อกที่ 2 · เกณฑ์ว่า "ข้อมูลพอหรือยัง"

ระบบไม่ปล่อยให้กดคัดกรองจนกว่าโปรไฟล์จะมีข้อมูลพอตัดสิน — เพื่อไม่ให้ได้ผลที่ดูน่าเชื่อถือ ทั้งที่ไม่มีข้อมูลรองรับ

เงื่อนไขต้องมี
ช่องหลัก (ประเภทกิจการ · ลักษณะสถานประกอบกิจการ · จำนวนลูกจ้าง · บทบาทในห่วงโซ่ธุรกิจ)อย่างน้อย 2 ช่อง
ช่องหลัก + รายการ (กิจกรรม · เครื่องจักร · สารเคมี · ใบอนุญาต · สถานะตามรายชื่อหน่วยงานกำกับ)รวมแล้วอย่างน้อย 3 กลุ่ม

เกณฑ์นี้ถูกตรวจ สองชั้น — ที่หน้าจอ (ปิดปุ่ม) และที่ server (ตอบ HTTP 428 ปฏิเสธ) ใช้สูตรเดียวกันทั้งสองฝั่ง จึงไม่มีกรณีที่กดได้แล้ว server ปฏิเสธโดยผู้ใช้ไม่เข้าใจว่าทำไม

// src/lib/supabase.js — ฝั่งหน้าจอ · api/law-screen.js profileTooThin() ใช้สูตรเดียวกัน
export function profileReady(p) {
  if (!p) return false
  const filled = [p.business_type, p.workplace_type, p.employee_count, p.value_chain_role]
    .filter(v => v !== null && v !== undefined && String(v).trim() !== '').length
  const lists = ['activities','machines','chemicals','licenses','regulator_status']
    .reduce((n, k) => n + ((Array.isArray(p[k]) && p[k].length) ? 1 : 0), 0)
  return filled >= 2 && (filled + lists) >= 3
}

บล็อกที่ 4 · เหตุผลที่ AI ต้องเขียนกลับมา

ระบบบังคับให้ AI เขียนเหตุผลในรูป "เงื่อนไขจากตัวบท — ข้อเท็จจริงจากโปรไฟล์ — จึงเข้า/ไม่เข้าข่าย" เหตุผลลอยๆ อย่าง "น่าจะเกี่ยวข้องเพราะเป็นกฎหมายความปลอดภัย" ถือว่าใช้ไม่ได้

✔ ใช้ได้    "ใช้กับสถานประกอบกิจการที่มีลูกจ้างตั้งแต่ 50 คนขึ้นไป
             — บริษัทมีลูกจ้าง 180 คน จึงเข้าข่าย"

✘ ใช้ไม่ได้  "น่าจะเกี่ยวข้อง เพราะเป็นกฎหมายด้านความปลอดภัย"

ถ้าข้อมูลในโปรไฟล์ไม่พอตัดสิน AI ต้องตอบ "ต้องข้อมูลเพิ่ม" พร้อมระบุว่าขาดอะไร ห้ามเดาเป็นเกี่ยวข้องหรือไม่เกี่ยวข้อง — การตอบว่าไม่รู้ไม่ใช่ความล้มเหลว แต่การเดาผิดคือสิ่งที่ทำให้ทะเบียนทั้งฉบับเชื่อถือไม่ได้

บล็อกที่ 7 · โปรไฟล์ถูกใช้ต่อที่ไหนอีก

การกรอกบริบทองค์กรครั้งเดียว ส่งผลต่อ 3 ฟีเจอร์

ฟีเจอร์ใช้โปรไฟล์ทำอะไร
คัดกรองความเกี่ยวข้องเทียบเงื่อนไขการใช้บังคับกับข้อเท็จจริงของบริษัท
เสนอสถานะการประเมินรายข้อตัดสินว่าข้อไหนเข้าเกณฑ์ "ไม่เกี่ยวข้อง" ได้ — และห้ามเดา ต้องชี้ได้ว่าโปรไฟล์ระบุอะไรไว้
รายงาน Gap Analysisอ้างขอบข่ายมาตรฐานที่รับรอง (iso_scope) เช่น ISO 45001 ข้อ 6.1.3 บนหัวรายงาน

บล็อกที่ 8 · สิ่งที่ระบบ ไม่ ทำ

ระบบไม่ทำเหตุผล
ไม่ตัดกฎหมายออกจากทะเบียนเองทะเบียนกฎหมายใช้ตอบผู้ตรวจ การหายไปของฉบับใดต้องมีคนรับผิดชอบ
ไม่เปลี่ยนสถานะข้อปฏิบัติให้อัตโนมัติผลประเมินต้องมีเจ้าของคำตัดสินเสมอ
ไม่เดาข้อมูลที่โปรไฟล์ไม่มีเดาผิดหนึ่งครั้ง ทำให้ทั้งทะเบียนถูกตั้งคำถาม
ไม่ถือผลของ AI เป็นข้อมูลทางการทุกผลต้องผ่านการยืนยันโดยคนก่อน
ไม่แทนที่การอ่านตัวบทจริงสรุปของ AI ใช้ทำความเข้าใจ ก่อนอ้างอิงกับผู้ตรวจต้องเปิดตัวบทเสมอ
