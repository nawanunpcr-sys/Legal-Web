## บล็อกที่ 2 · เกณฑ์ว่า "ข้อมูลพอหรือยัง"

ระบบไม่ปล่อยให้กดคัดกรองจนกว่าโปรไฟล์จะมีข้อมูลพอตัดสิน — เพื่อไม่ให้ได้ผลที่ดูน่าเชื่อถือ
ทั้งที่ไม่มีข้อมูลรองรับ

| เงื่อนไข | ต้องมี |
|---|---|
| ช่องหลัก (ประเภทกิจการ · ลักษณะสถานประกอบกิจการ · จำนวนลูกจ้าง · บทบาทในห่วงโซ่ธุรกิจ) | อย่างน้อย **2 ช่อง** |
| ช่องหลัก + รายการ (กิจกรรม · เครื่องจักร · สารเคมี · ใบอนุญาต · สถานะตามรายชื่อหน่วยงานกำกับ) | รวมแล้วอย่างน้อย **3 กลุ่ม** |

เกณฑ์นี้ถูกตรวจ **สองชั้น** — ที่หน้าจอ (ปิดปุ่ม) และที่ server (ตอบ HTTP 428 ปฏิเสธ)
ใช้สูตรเดียวกันทั้งสองฝั่ง จึงไม่มีกรณีที่กดได้แล้ว server ปฏิเสธโดยผู้ใช้ไม่เข้าใจว่าทำไม

```js
// src/lib/supabase.js — ฝั่งหน้าจอ · api/law-screen.js profileTooThin() ใช้สูตรเดียวกัน
export function profileReady(p) {
  if (!p) return false
  const filled = [p.business_type, p.workplace_type, p.employee_count, p.value_chain_role]
    .filter(v => v !== null && v !== undefined && String(v).trim() !== '').length
  const lists = ['activities','machines','chemicals','licenses','regulator_status']
    .reduce((n, k) => n + ((Array.isArray(p[k]) && p[k].length) ? 1 : 0), 0)
  return filled >= 2 && (filled + lists) >= 3
}
```

## บล็อกที่ 3 · โครงข้อมูลที่เก็บ

```
lg_company_profile  (แถวเดียวทั้งระบบ · บังคับ id = 1)
├── ฟิลด์ที่ query ได้        business_type · workplace_type · employee_count
│                             contractor_count · site_count · value_chain_role
└── ฟิลด์รายการ (jsonb)      sites · activities · machines · chemicals
                              licenses · regulator_status · iso_scope · extra
```

**ที่มาของโครง** — ไม่ได้ออกแบบขึ้นเอง แต่มาจากเหตุผลที่ทีมงานเขียนไว้จริงในช่อง "หมายเหตุ"
ของเอกสาร F-259 ซึ่งแยกได้ 4 ประเภท เรียงตามที่พบบ่อยที่สุด:

| # | ประเภทเหตุผล | ตัวอย่างจากเอกสารจริง | เก็บที่ฟิลด์ |
|---|---|---|---|
| 1 | สถานะตามรายชื่อของหน่วยงานกำกับ | "กสทช. แจ้งว่า JasTel ไม่อยู่ในรายชื่อหน่วยงาน CII" | `regulator_status` |
| 2 | ขนาดองค์กร | "ลูกจ้างตั้งแต่ 50 คนขึ้นไป" | `employee_count` |
| 3 | ลักษณะทางกายภาพ | "ชั้น G และ P10 · Gen เกิน 2,500 ลิตร" | `workplace_type` · `machines` |
| 4 | บทบาทในห่วงโซ่ธุรกิจ | "เป็นผู้ใช้งานสายใยนำแสง ไม่ใช่ผู้ผลิต" | `value_chain_role` |

## บล็อกที่ 4 · เหตุผลที่ AI ต้องเขียนกลับมา

ระบบบังคับให้ AI เขียนเหตุผลในรูป **"เงื่อนไขจากตัวบท — ข้อเท็จจริงจากโปรไฟล์ — จึงเข้า/ไม่เข้าข่าย"**
เหตุผลลอยๆ อย่าง "น่าจะเกี่ยวข้องเพราะเป็นกฎหมายความปลอดภัย" ถือว่าใช้ไม่ได้

```
✔ ใช้ได้    "ใช้กับสถานประกอบกิจการที่มีลูกจ้างตั้งแต่ 50 คนขึ้นไป
             — บริษัทมีลูกจ้าง 180 คน จึงเข้าข่าย"

✘ ใช้ไม่ได้  "น่าจะเกี่ยวข้อง เพราะเป็นกฎหมายด้านความปลอดภัย"
```

ถ้าข้อมูลในโปรไฟล์ไม่พอตัดสิน AI **ต้องตอบ "ต้องข้อมูลเพิ่ม"** พร้อมระบุว่าขาดอะไร
ห้ามเดาเป็นเกี่ยวข้องหรือไม่เกี่ยวข้อง — การตอบว่าไม่รู้ไม่ใช่ความล้มเหลว
แต่การเดาผิดคือสิ่งที่ทำให้ทะเบียนทั้งฉบับเชื่อถือไม่ได้

## บล็อกที่ 5 · ผลของ AI ยังไม่ใช่ผลของทะเบียน

นี่คือกติกาที่สำคัญที่สุดของทั้งระบบ

```
        AI เสนอ                    เจ้าหน้าที่ตัดสิน              ผลของทะเบียน
   ┌────────────────┐          ┌────────────────────┐        ┌──────────────┐
   │ verdict        │          │ confirmed_verdict  │        │ final_verdict│
   │ confidence     │  ────▶   │ confirmed_by       │ ────▶  │              │
   │ reason         │          │ confirmed_at       │        │ ยังไม่คัดกรอง │
   │ suggested_at   │          │ confirm_note       │        │ จนกว่าจะยืนยัน│
   └────────────────┘          └────────────────────┘        └──────────────┘
     เก็บไว้ถาวร                  เก็บคู่กัน ไม่ทับกัน            ใช้คำตัดสินของคน
                                                                เท่านั้น
```

| กติกา | บังคับที่ไหน |
|---|---|
| ไม่มีคนยืนยัน = ยังไม่คัดกรอง (ไม่ตกไปใช้ค่าของ AI) | โค้ด + view `lg_law_relevance_view` |
| ยืนยันแล้วต้องรู้ว่าใครยืนยัน | CHECK ในฐานข้อมูล |
| เห็นต่างจาก AI ต้องเขียนเหตุผล | CHECK ในฐานข้อมูล + ปุ่มบันทึกถูกปิดจนกว่าจะกรอก |
| ยืนยันว่า "ไม่เกี่ยวข้อง" แล้ว **ห้ามเปลี่ยนสถานะข้อปฏิบัติให้อัตโนมัติ** | โค้ด — หน้าจอขึ้นข้อความให้ไปเปลี่ยนทีละข้อเอง |

เหตุผลของข้อสุดท้าย: ผู้ตรวจ ISO ต้องตอบได้ว่า**ใครเป็นคนตัดสิน**ว่าข้อนั้นไม่เกี่ยวข้อง
และด้วยเหตุใด · ระบบเปลี่ยนให้เองจะทำให้ 575 ข้อไม่มีเจ้าของคำตัดสินสักข้อ

## บล็อกที่ 6 · การทำงานเป็นชุด

การคัดกรอง 150 ฉบับ = เรียก AI 150 ครั้ง จึงไม่ยิงจากหน้าจอ แต่ผ่านคิว

```
   หน้าจอ                    ฐานข้อมูล                    server
   ──────                    ─────────                    ──────
   "เข้าคิวทั้งหมด"  ──▶  lg_agent_queue
                            (pending × 150)
                                  │
   "ประมวลผลคิว"    ──▶  ─────────┴────────▶  api/queue-run.js
                                                  │
                                                  ├─ หยิบทีละงาน
                                                  ├─ เรียก law-screen
                                                  ├─ เว้นจังหวะ 1.2 วินาที
                                                  └─ หยุดเองก่อนครบ 270 วินาที
                                                        │
   "เหลืออีก N ฉบับ" ◀───────────────────────────────────┘
   (กดต่อได้)
```

| ค่าที่ตั้งไว้ | ค่า | เหตุผล |
|---|---|---|
| งบเวลาต่อคำขอ | 270 วินาที | Vercel ตัดที่ 300 วินาที เผื่อไว้ 30 วินาที |
| เวลาต่อ 1 ฉบับ | 60 วินาที | เหลือน้อยกว่านี้ไม่เริ่มงานใหม่ ไม่งั้นเสียทั้งเวลาและโควตา |
| เว้นจังหวะ | 1.2 วินาที | กันชนเพดานความถี่ของ Anthropic |
| โควตางานคิว | 60 ครั้ง/นาที | แยกจากโควตาปุ่มที่คนกด (10 ครั้ง/นาที) จึงไม่เบียดกัน |

งานที่ค้างเพราะคำขอถูกตัดกลางคัน จะถูกนำกลับเข้าคิวอัตโนมัติในรอบถัดไป

## บล็อกที่ 7 · โปรไฟล์ถูกใช้ต่อที่ไหนอีก

การกรอกบริบทองค์กรครั้งเดียว ส่งผลต่อ 3 ฟีเจอร์

| ฟีเจอร์ | ใช้โปรไฟล์ทำอะไร |
|---|---|
| **คัดกรองความเกี่ยวข้อง** | เทียบเงื่อนไขการใช้บังคับกับข้อเท็จจริงของบริษัท |
| **เสนอสถานะการประเมินรายข้อ** | ตัดสินว่าข้อไหนเข้าเกณฑ์ "ไม่เกี่ยวข้อง" ได้ — และห้ามเดา ต้องชี้ได้ว่าโปรไฟล์ระบุอะไรไว้ |
| **รายงาน Gap Analysis** | อ้างขอบข่ายมาตรฐานที่รับรอง (`iso_scope`) เช่น ISO 45001 ข้อ 6.1.3 บนหัวรายงาน |

## บล็อกที่ 8 · สิ่งที่ระบบ **ไม่** ทำ

| ระบบไม่ทำ | เหตุผล |
|---|---|
| ไม่ตัดกฎหมายออกจากทะเบียนเอง | ทะเบียนกฎหมายใช้ตอบผู้ตรวจ การหายไปของฉบับใดต้องมีคนรับผิดชอบ |
| ไม่เปลี่ยนสถานะข้อปฏิบัติให้อัตโนมัติ | ผลประเมินต้องมีเจ้าของคำตัดสินเสมอ |
| ไม่เดาข้อมูลที่โปรไฟล์ไม่มี | เดาผิดหนึ่งครั้ง ทำให้ทั้งทะเบียนถูกตั้งคำถาม |
| ไม่ถือผลของ AI เป็นข้อมูลทางการ | ทุกผลต้องผ่านการยืนยันโดยคนก่อน |
| ไม่แทนที่การอ่านตัวบทจริง | สรุปของ AI ใช้ทำความเข้าใจ ก่อนอ้างอิงกับผู้ตรวจต้องเปิดตัวบทเสมอ |
